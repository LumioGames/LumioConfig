# LumioConfig 网页编辑器重设计提示词（v3：排版 / 布局 / 交互，2026-09-03）

> 用途：把本文整段交给负责重设计的 Agent（或设计师）。读完应能独立产出设计稿、可点原型与实现计划，不依赖本对话。v2 实现指引（`2026-09-02-web-editor-design-prompt.md`）与 `docs/decisions/0-7`、`0-8` 继续有效——本文只改「长什么样、怎么用」，不改「数据归谁管、走什么链路」。

---

## 0. 你的角色与任务

你是 LumioConfig 网页编辑器的**产品设计师 + 前端架构师**。

现状：v1（`editor/`）功能链路已经跑通——投影、四态、草稿自动保存、预检、提交、单元格级三方合并、CSV/TSV 导出，Playwright E2E 全绿。但界面是「把所有面板堆在表格下面」的 POC 级产物：表格被挤到不足一半高度，主要动作藏在页面中部，状态信息是一行原始字段，冲突处理靠 `window.prompt`。它能演示，不能日常用。

任务：在**不改 Host 契约、不改权威边界、不换技术栈**的前提下，重新设计信息架构、布局、视觉系统与交互，并给出能落到现有代码上的分卡实现计划。

工作顺序：**先出设计与原型 → Owner 拍板 → 再写代码。** 未拍板前不得改 `editor/src/`。

Owner 的设计原则是「如无必要勿增实体」：每个新面板、新概念、新依赖都要说清为什么非有不可；能在一个地方解决的不要拆成两个；两个方案里选更少实体的那个，除非能证明多出来的实体换来了明确的可用性收益。

## 1. 产品是什么、给谁用

- 一句话：在浏览器里用飞书表格的手感打开、浏览、编辑本仓的配置表；`Ctrl+S` 存本地草稿；「提交补丁」把改过的格子打成带基线指纹的补丁送进机器门（M2），机器门做三方合并；成功后按设置自动 commit、自动导表。**编辑器不是权威源，没有上线按钮。**
- 用户是**一个人**：策划或 TD，本机使用。日常 **80% 的改动由 AI 提补丁**，人用编辑器做三件事：**看表、微调几格、核对 AI 改了什么。**
- 不是多人协同产品：无账号、无公网、无实时协作、无桌面壳。
- 表的规模：目前 3 张表（skills / effects / drops）、每表几行到几千行、列数 5–30；性能基线见 `editor/docs/poc-benchmark.md`（10 万格粘贴已测）。

## 2. 现状与问题（2026-09-03 在 1440×900 实测）

### 2.1 现有布局

│ 草稿自动保存 │ ┌──────────────────────────────────────────────────┐ │
│ drops     │ │ 表格（约占主区 45% 高度）                          │ │

│ skills ●  │ └──────────────────────────────────────────────────┘ │

对应代码：`editor/src/app/App.tsx` 的 JSX（`app-shell` → `TableList` + `app-main`），`editor/src/styles/app.css`（`app-main` 是 `grid-template-rows: 1fr auto auto 36px`，但实际最多塞 8 个子元素），`editor/src/panels/*.tsx`。

### 2.2 问题清单

**布局与空间**

1. 表格是唯一的工作面，却只有不到一半高度；`DiffPreview`（`max-height: 180px`）、`ExportPanel`（带外边距的卡片）、`SettingsPanel` 在 Host 模式下**常驻**，哪怕内容是空的（「尚未预检」+ 空表头）。
2. 面板是无条件竖向堆叠，没有折叠、没有页签、没有按需出现；冲突表、错误列表、「刷新」按钮出现时再往下挤。
3. 左栏 220px 只有表名和 `· N` 脏格数；没有搜索、行数、Schema 摘要。

**表格区**

4. Univer 通用工具栏和「开始 / 公式 / 数据」页签全量露出：字体、加粗、斜体、填充色、边框、数字格式、公式栏……而 0-7 §4 明令禁止公式持久化、合并单元格、把颜色当数据。当前只在 `univer.ts` 的 `HIDDEN_MENUS` 里藏了合并、插列、插函数、粘贴公式四类，其余都是**点了会被拦截器拒绝的死入口**。
5. 右键菜单被自定义的四态菜单整体替换（只有「设为空字符串 / 设为 null / 恢复默认 / 设为缺列」四项），Univer 原生的插行 / 删行 / 复制 / 粘贴等右键入口不可达。
6. 空表也渲染 40 行（`Math.max(40, rows + 20)`），枚举列在每个空行都画一个下拉控件，视觉噪音大。
7. 单工作表却保留 Univer 底部工作表页签栏。
8. 四态只靠灰色斜体文字区分（`projection.ts` 的 `STYLES`），0-7 §5 要求的 `missing` / `""` / `∅` / `默认` 徽标没有形成可一眼辨认的视觉语言；改过的格（脏格）没有任何高亮。
9. 干净仓库打开 `skills`，`name` / `display_name` / `icon` 三列显示为红色（`invalid` 样式 `#C5221F`），没有提示说明为什么——**需要先核实这是投影误判还是真实校验失败**，设计要覆盖「无效格必须能解释原因」。

**状态与反馈**

10. 状态栏是一行原始字段：完整 sha256 指纹、英文阶段名 `ReadyClean`、「脏格 0」；最重要的信息（例如 `另一个标签页已保存，请刷新`、仓库已变化）是最右侧的一小段红字，极易漏看。
11. 11 个会话阶段（`Opening / ReadyClean / ReadyDirty / SavingDraft / Validating / ReadyToSubmit / Submitting / Conflicted / Stale / Failed / Closed`）没有各自的视觉表达，按钮可用性变化没有解释。
12. 页面标题是 `LumioConfig Univer POC`。

**主要动作**

13. 「预检」「提交补丁」是两个默认样式的小按钮，落在页面中部；旁边是一行技术口径 `autoCommit=true，autoExport=false`。用户无法一眼回答「我点提交会发生什么」（提交到哪个分支、会不会 commit、会不会导表、改了几处）。
14. 补丁预览表只有 `表 / 行 / 操作 / 改动` 四列，`update` 的改动挤成一串 `col: a → b; col: c → d`，不能点击跳到格子。

**冲突与错误**

15. `ConflictPanel` 是 7 列宽表，每行最多 6 个按钮；「手工输入」走 `window.prompt`；没有进度（已解决 / 剩余）。
16. `ErrorPanel` 是裸 `<ul>` 里的 `CODE: message` 按钮；`App.tsx` 没有把 `onJump` 传进去，点击无效，无法定位到出错的格。

**信息缺失**

17. 列的元数据（类型、是否必填、默认值、枚举 / 引用目标、min / max、S/C/V 可见性）在界面上完全不可见，用户要读 `schemas/*.json` 才知道一列是什么意思。
18. 「核对 AI 改了什么」这条最重要的旅程**没有任何 UI**：没有相对基线的差异视图，没有「自某次修订以来的改动」。
19. 设置面板只有一个 `autoCommit` 复选框和「已写入 local.json」，是技术口径不是用户口径。

**细节**

20. 快捷键只有 `Ctrl+S`；没有命令面板、没有快捷键提示。
21. 只有浅色主题；固定 `color-scheme: light`。
22. 每个面板都没有空态 / 加载态 / 出错态设计。

## 3. 不可动的边界（设计必须遵守）

以下来自 `docs/decisions/0-7`、`0-8`，冲突时以决议原文为准；发现设计非得突破某条，停下上报，不得自行改写决议。

- **所有权与单向链路**：语义只在 Python；Univer 只管交互；身份只在 `ProjectionMap`；视图状态只在浏览器 `localStorage`。前端不解析、不写 `tables/ registry/ schemas/`，不自判 M2 合法性。
- **动作命名固定**：`Ctrl+S` = 保存本地草稿；正式动作只有四个——**预检、预览补丁、提交补丁、导出**。界面上不得出现「保存到仓库」「上线」「激活」「强制覆盖」。
- **状态机与按钮可用性**（0-8 §8）：`Submitting` 期间全部禁用；`Stale` 只允许合并仓库改动；`Conflicted` 只允许冲突面板动作与取消；`SCHEMA_CHANGED` 只允许刷新；`DRAFT_VERSION_CONFLICT` 只允许刷新。
- **冲突只能逐格选择或取消**，解决后必须重生成补丁并重跑 validate + apply。
- **四态语义与 Delete 键规则**（0-7 §5）：`@missing` / `""` / `null` / `@default` 与普通值互不坍缩；required 列不能设缺列；Delete 按列默认值 / required 决定落到哪一态。
- **稳定身份**：`id` 列只读；新行 `id` 显示「合入时发号」；复制行取新 `draftRowKey`；排序 / 筛选不改身份、不产生行序补丁。
- **禁止操作清单**（0-7 §4）：公式持久化、合并单元格、宏、图表、透视表、外链、插 / 删 Schema 列、颜色当数据、筛选隐藏当删除、排序后行序写回。设计目标是**让这些入口根本不出现**，而不是出现后被拦。
- **导出单向**：CSV / TSV，一表一文件 + README，不导回。
- **技术栈固定**：React + TypeScript（strict）+ Vite；表格内核 Univer OSS `0.25.x`（`preset-sheets-core` + filter / sort / data-validation / find-replace）；**禁止 `@univerjs-pro/*`**；Host 是 Python 标准库，不加依赖；不做桌面壳。
- **CSP**：`default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'`——**不能引外部字体、CDN 脚本、外部图标**；字体走系统栈或自托管，图标内联 SVG。
- **Host API 形状不变**（v2 指引 §3.3）：`/api/session`、`/api/tables/{t}`、`/api/drafts/{t}`（含 `/rebase`）、`/api/patch/validate|apply`、`/api/export`、`/api/exports/{id}/{file}`、`/api/events`、`/api/settings/local`、`DELETE /api/session`。设计若需要新数据，写成「需要新增 API」单独列出，理由充分，不在前端伪造。
- **E2E 契约**：`editor/tests/e2e/*.spec.ts` 依赖的 `data-testid` 要么保留，要么在同一张卡里同步更新测试；不得让 E2E 失守后再补。
- **构建产物** `src/lumio_config/editor_static/` 随源提交，`pnpm build` 必须可复现。

## 4. 要支撑的五条用户旅程（设计围绕这些展开，逐条给出屏幕流）

| # | 旅程 | 起点 → 终点 | 现状痛点 |
| --- | --- | --- | --- |
| J1 | **看表** | 打开 → 找到表 → 扫一遍 → 筛选 / 排序 / 冻结 → 看懂每列的含义与约束 | 列元数据不可见；表格太矮；空行噪音 |
| J2 | **微调几格** | 改值（含枚举 / 引用 / 数值）→ 即时校验反馈 → 四态切换 → 自动存草稿 → 预览补丁 → 预检 → 提交 → 看到结果（新指纹、发号、commit） | 脏格无高亮；动作分散；「提交会发生什么」不透明 |
| J3 | **核对 AI 改了什么** | AI 提交补丁后打开表 → 看到相对上次 / 相对某修订的改动 → 跳到改动格 → 认可或微调 | 完全没有此视图（见 §5.9） |
| J4 | **处理过期 / 冲突 / Schema 变化** | 收到 `Stale` → 自动合并 → 有冲突则逐格三选一 → 重新预检提交；`SCHEMA_CHANGED` → 刷新重放 | 冲突表拥挤、`window.prompt`、无进度；状态提示藏在角落 |
| J5 | **导出** | 选表 / 格式 / 来源 / S·C·V 目标 → 导出 → 下载 | 常驻卡片占空间；不需要时也在 |

## 5. 设计要求

### 5.1 信息架构与布局（给方案对比，推荐一个，Owner 拍板）

至少比较两个候选，写明各自实体数与取舍：

- **候选 A：三栏 + 底部抽屉。** 顶栏（表名、修订 / 分支、草稿状态、主要动作组、溢出菜单）；左栏表列表（可折叠到图标）；中央表格占满；右侧「检查器」（当前格 / 列 / 行的上下文：Schema 约束、四态、基线值 → 当前值、错误原因；可折叠）；底部抽屉（补丁预览 / 错误 / 冲突 / 导出 分页签，默认收成一条带计数的 32px 状态条，按需展开）。
- **候选 B：两栏 + 右侧多功能面板。** 不设底部抽屉，所有次要内容都进右侧面板分页签（检查器 / 补丁 / 错误 / 冲突 / 导出），面板可折叠。实体更少，但补丁预览宽度受限。
- 允许提出候选 C，但必须说明它比 A / B 少了什么或解决了什么。

硬要求：默认状态下表格区域 ≥ 主区高度 75%；任何面板都只在有内容或用户主动打开时占空间。

### 5.2 Univer 表面裁剪

- 调研 `UniverSheetsCorePreset` 在 `0.25.x` 的 `header / toolbar / formulaBar / footer / menu / contextMenu` 等配置项与菜单隐藏机制，给出**允许项白名单**：撤销 / 重做、查找 / 替换、筛选、排序、冻结、缩放、插入 / 删除 / 复制行、复制 / 剪切 / 粘贴。
- 禁止项（字体、字号、加粗、斜体、颜色、填充、边框、对齐、数字格式、合并、公式栏、插列、函数、图表等）**不可见**，而不是可见但被拦。若某项无法通过配置隐藏，写清楚需要什么 CSS / 插件手段及其风险。
- 右键菜单合并成一个：四态动作 + 允许的行操作 + 复制粘贴；不再整体替换原生菜单导致行操作不可达。
- 空行策略：表末只留少量可编辑空行（建议 ≤ 5），或改成显式「新增行」动作；空行不预渲染下拉控件。
- 单工作表不显示底部页签栏；缩放控件若保留，放到顶栏或状态条。

### 5.3 视觉系统

- 定义设计令牌：颜色（含语义色：脏格、新行、待删除行、冲突、无效、四态、只读）、间距、圆角、阴影、字号阶梯、行高、密度（配置表偏紧凑：行高 24–28px）。
- 字体：中英混排优先的系统字体栈（CSP 禁外链）；数值 / id 列使用等宽或 `tabular-nums`。
- 浅色 + 深色两套主题，用 `data-theme` 切换并记入 `localStorage`（0-7 §4 允许「主题」作为视图状态）；Univer 自身主题也要跟随。
- 状态不能只靠颜色表达：脏格、无效、四态、新行、删除行各自有图标 / 徽标 / 边框等第二通道；对比度 ≥ 4.5:1。
- 图标内联 SVG（可用 `better-icons` 技能搜索 Iconify 库取 SVG，再内联进源码，不走运行时外链）。

### 5.4 会话状态 → 界面映射

给出一张表：11 个阶段 × {顶栏状态文案、状态色、可用动作、横幅 / 弹层、状态条}。要求：

- `Stale`、`Conflicted`、`Failed`、`SCHEMA_CHANGED`、`DRAFT_VERSION_CONFLICT`、离线 必须是**页面顶部横幅级**提示，带唯一允许的动作按钮，不能只在状态条角落。
- 阶段名全部翻译成用户口径（候选：`ReadyClean` → 「与仓库一致」、`ReadyDirty` → 「N 格未提交」、`ReadyToSubmit` → 「预检通过，可提交」、`Stale` → 「仓库已更新，正在合并」……），英文阶段名只在 `title` / 调试信息里出现。
- 状态条内容重排：表名 / 行数 / 草稿版本 / 脏格数 / 在线 保留，指纹缩到 8 位并点击可复制全文，`hint` 类消息改走横幅或 toast。

### 5.5 单元格语义

- 四态渲染规范：`missing` / `""` / `∅` / `默认` 四种徽标的形状、颜色、位置；调研 Univer 自定义单元格渲染（render extension）的成本，若过重则退回「文本徽标 + 样式」，但必须一眼可辨、与普通值不混淆。
- 脏格高亮 + 悬停 / 检查器显示「基线 → 当前」；新行整行标记，`id` 格显示「合入时发号」；标记删除的行用删除线 + 可撤销。
- 类型编辑器：枚举下拉、引用选择（显示目标表的 `name` + `display_name`）、数值范围提示、必填提示；无效格必须能看到**原因**（点格 → 检查器 / 悬停）。
- 列头显示类型、必填、S/C/V 可见性、默认值的紧凑标识；列头悬停或检查器显示 Schema 描述全文。

### 5.6 补丁预览与提交（预览补丁 / 预检 / 提交补丁）

- 主要动作组放顶栏右侧，顺序与状态机一致：预检 → 提交补丁；按钮态跟状态机；提交前用一句人话说明后果：「将把 3 处改动提交到 `main`，并以 `config(skills): …` 自动 commit；不导表」。`autoCommit=false` 时常显「N 处未提交」。
- 补丁预览按行分组：`create / update / rename / delete` 各有图标；`update` 逐列显示 `expect → set`；每项可点击跳转并选中格；顶部有人话摘要（来自 `summary`）。
- 提交成功：toast + 结果面板（新指纹、`assignedIds` 映射、commit id / 分支、导出文件数），表格自动重载并把 `draft:` 行替换成正式 `id`。

### 5.7 冲突解决

- 每个冲突是一张卡：`打开时 / 仓库当前 / 我的草稿` 三列并排，单选「采仓库值 / 采我的值 / 手工输入 / 恢复默认 / 设为 null」，手工输入是内联输入框，不用 `window.prompt`。
- 顶部进度「已解决 3 / 7」，全部解决后出现「重新预检并提交」；`DELETED_ROW_CONFLICT` 的卡只有「放弃我的改动 / 取消本次提交」。
- 冲突卡与表格双向联动：点卡跳格，格上有冲突标记。

### 5.8 错误

- 按表 / 行分组，显示 `code`、`message`、`suggestion`；点击跳转并选中格；把 `onJump` 真正接线。
- 校验错误与预检响应同步刷新；无错误时不占空间。

### 5.9 「核对 AI 改了什么」视图（J3）

- 先用现有数据能做到的：打开表时 `ProjectionMap.baseCells` 与草稿的差异（我的未提交改动）已可展示；「与上次打开相比」可用 `localStorage` 记住上次看到的 `sourceFingerprint` 做提示。
- 「自某次修订以来 AI 改了什么」需要 Host 提供历史 / 差异数据（例如某修订的表快照或 diff），**现有 API 没有**。设计要给出该视图的 UI 与它最少需要的数据形状，作为「需要新增 API」单独列卡，不在本轮实现；不得在前端调用 git。

### 5.10 表列表

- 搜索 / 过滤；每项显示行数、脏格数、是否有未合并草稿、是否冲突；当前表高亮；可折叠为窄栏。
- 「草稿自动保存，不写权威源」这类说明移到状态条或首次打开的提示，不常驻占位。

### 5.11 键盘与命令

- 给出快捷键表（候选：`Ctrl+S` 存草稿、`Ctrl+Enter` 预检、`Ctrl+Shift+Enter` 提交、`Ctrl+K` 命令面板 / 切表、`Ctrl+B` 折叠侧栏、`Esc` 关闭面板 / 抽屉、`F2` 编辑格、`Shift+F10` 右键菜单）；所有按钮的 tooltip 带快捷键。
- 五条旅程都要能只用键盘走完。

### 5.12 空态、加载态、出错态

- 每个面板与整页都要有：表加载中、表为空、未预检、无错误、无冲突、导出中、Host 离线、token 失效。
- Host 离线 / token 失效 是整页级阻断，给出重连指引（重新从终端启动 `serve` 并打开新链接）。

### 5.13 文案

- 全部用户可见文本用中文用户口径，不出现 JSON 键名、英文阶段名、文件名（`local.json`）；设置项写成「提交后自动 commit 到当前分支」「提交后自动导表」。
- 给一张文案表：现有文案 → 新文案。

### 5.14 可访问性

- 焦点环、菜单 / 抽屉 / 对话框的 ARIA 角色与焦点管理、对比度；Univer 之外的自定义组件不得吞掉键盘事件。

**验收（设计稿与原型阶段）**：
