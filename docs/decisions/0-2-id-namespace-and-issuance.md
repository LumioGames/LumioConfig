# 0-2 ID 命名空间与发号

> **并行期声明。** 本决议暂落本仓、不占架构仓 ADR 号。原因是并行期避免与 RM-00011 抢号：架构仓 `docs/adr/` 与 `.spec/decisions/` 由 RM-00011 编排会话唯一写入，ADR 编号在合并时现查当时最高号再占。后人不得把本文件的存在理解成架构仓流程遗漏。

对应设计概要 §5 阶段 0 表「ID 命名空间与发号（扩展 ADR-007）」；裁决依据为板 A.3。本仓只在架构仓已授权的配表域内自治发号，不改 ADR-007 正文。

## 决定

每行三个身份，缺一不可、互不顶替：

| 身份 | 例子 | 谁写 | 可否改 | 用途 |
| --- | --- | --- | --- | --- |
| 名字 | `fireball` | 补丁 | 可以改 | 人/AI 说话、补丁寻址 |
| 终身编号 | `40001` | 发号台在合入时串行分配 | 永不改、永不给别人 | 存档、网络、回放、GAS TypeId |
| 座位号 | 本次编译的稠密下标 `0..n-1` | 导表器按终身编号排序现算 | 每版可重排 | 仅运行时内部；**禁止存档** |

规则：

1. **补丁只写名字，不写终身编号。** 出现 `id` 字段即为 `PATCH_ASSIGNS_ID`。
2. **发号在 apply 时加锁串行。** 新号 = 该表已知终身编号（含墓碑）的最大值 + 1，跳过墓碑。两个并发 create 不得拿到同一号。
3. **删除进墓碑。** `registry/tombstones.json` 登记退休编号；校验拒绝把墓碑号写回活表；分配器永不复用。
4. **改名保留终身编号。** `rename` 只改 `name` 与 registry 的名字映射，lookup 按终身编号仍能找到该行。
5. **列的稳定序号**归 Schema 演进，不占这三层行身份。

首版技能 / 效果 / 掉落的域内种子沿用已有编号（40000 / 50000 / 60000 段，含墓碑占位）。跨仓命名空间授权仍归架构仓 ADR-007，本仓不自创公共域。

## 明确不做

- 不把座位号写入 `tables/`、`registry/` 或存档。
- 不在架构仓 ID Registry 为每一行占号。
- 不在本决议占用架构仓 ADR 号。
