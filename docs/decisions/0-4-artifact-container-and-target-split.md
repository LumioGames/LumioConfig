# 0-4 产物容器与三端切分

> **并行期声明。** 本决议暂落本仓、不占架构仓 ADR 号。原因是并行期避免与 RM-00011 抢号：架构仓 `docs/adr/` 与 `.spec/decisions/` 由 RM-00011 编排会话唯一写入，ADR 编号在合并时现查当时最高号再占。后人不得把本文件的存在理解成架构仓流程遗漏。

对应设计概要 §5 阶段 0 表「产物容器与三端切分（四层清单、S/C/V 标签、披露门禁、签名防回滚）」；裁决依据为板 B.3 / C.1。

## 决定

1. **四层产物骨架：** 发布清单 → 分端投影清单 → 表描述 → 块描述。首版文本导出落在 `build/export/`：`manifest.json` + `server|client|voxel/<table>.json`。字段细节实现期可修，转正走架构仓候选 ADR。
2. **S / C / V 标签。** 每列 `visibility` 为 `S`/`C`/`V` 的非空组合；不写则默认只给服务器。客户端投影里机密列必须物理不存在，不是加密藏起来。
3. **披露门禁。** 某列第一次标 `C` 必须出现在生产激活单上。本仓阶段 1 不实现人门 UI，但导出器不得把未标 `C` 的列写进 client 投影。
4. **跨端引用。** 对某端可见的 ref，其目标 id 列也必须对该端可见，否则 `HIDDEN_REF_TARGET`。
5. **签名防回滚。** 生产装载只接受人门签过的 Revision；防回滚计数、过期、信任链轮换细则借鉴 TUF，搬入架构仓时写进候选 ADR，本仓不发明信任链实现。
6. 产物是生成物：只读、禁止手改、必须能从文本源重建。`generated/` 与实现仓 `contract-mirror/` 不是本仓手写面。

## 明确不做

- 第一期不做压缩、分块大小或增量编译。
- 不在本仓实现生产签名工具。
- 不在本决议占用架构仓 ADR 号。
