# 0-1 权威源与补丁通道

> **并行期声明。** 本决议暂落本仓、不占架构仓 ADR 号。原因是并行期避免与 RM-00011 抢号：架构仓 `docs/adr/` 与 `.spec/decisions/` 由 RM-00011 编排会话唯一写入，ADR 编号在合并时现查当时最高号再占。后人不得把本文件的存在理解成架构仓流程遗漏。

对应设计概要 §5 阶段 0 表「权威源与补丁通道（文本格式三纪律、双门）」；裁决依据为架构仓 `docs/specs/2026-08-30-config-table-architecture-decisions.md` 板 A.1 / A.2a / A.1c / A.1d。读取时以架构仓 `origin/main` 为准。

## 决定

1. **权威源是 Git 管理的规范化文本。** 每张表由 `schemas/<table>.json`、`tables/<table>.txt` 和 `registry/` 中的行号/墓碑共同构成。Excel、网页编辑器和导出 JSON 都只是窗口或产物，不能覆盖文本真身。
2. **唯一写路径是结构化补丁。** AI 和人走同一条通道：补丁 → 机器门 → 合入权威源。人不直接改文件；编辑器保存必须生成逐格补丁，禁止整文件覆盖。
3. **文本格式三纪律：**
   - 单元格四态可区分：缺列 `@missing`、空字符串 `""`、明确空值 `null`、吃默认 `@default`。
   - 每行行首带终身编号（源表列 `id`）；补丁本身不写该编号，见 0-2。
   - 机器格式化器统一排版，CI 以 `python tools/lumio_config.py format --check` 强制；人/AI 不手排。
4. **行级 Git 合并。** 格式化器在数据行之间输出空行，使两个补丁改同一张表的不同行时，Git 三路合并能自动合入。
5. **双门：** 合入权威源是机器门（schema / 类型 / 引用 / 可见性全过即自动合入）。生产激活是人门，本决议不实现人门，只钉「合入 ≠ 上线」。

## 明确不做

- 不把 Excel 当源，不做 Excel 双向同步。
- 表里不写 `if`、脚本列或蓝图式逻辑。
- 不在本决议占用架构仓 ADR 号。
- 不把源表后缀改为 `.md`（2026-09-02 评估）。MD 的渲染收益与行间空行互斥，而空行保证同行冲突带 ours/theirs 标记，对 AI 合并最友好；重议条件为多分支并行改表成为常态。
