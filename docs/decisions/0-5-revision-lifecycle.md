# 0-5 版本生命周期

> **并行期声明。** 本决议暂落本仓、不占架构仓 ADR 号。原因是并行期避免与 RM-00011 抢号：架构仓 `docs/adr/` 与 `.spec/decisions/` 由 RM-00011 编排会话唯一写入，ADR 编号在合并时现查当时最高号再占。后人不得把本文件的存在理解成架构仓流程遗漏。

对应设计概要 §5 阶段 0 表「版本生命周期（实例绑定、开发 reload、备齐纪律、回放钉版）」；裁决依据为板 D.3 / D.3d / D.1 / D.2 / D.4。本仓不实现装载器，只钉语义，供后续 M9/M10 遵守。

## 决定

1. **生产：实例绑定整套 Revision。** 一台服务器开机装上哪一版就用到退役，运行中不换表。滚动更新时新旧实例短暂并存，连接靠指纹配对，连错拒绝并重连。
2. **开发 reload。** 使用同一套「攒好新版 → 帧间隙整套切换」原语，跳过人门签名。禁止半帧新半帧旧。生产不用 reload。
3. **备齐纪律。** 帧内 `TryGet` 零 I/O。下载/解压只发生在显式备货。实例开门或进场景前，必需表没备齐就不接客。
4. **回放钉版。** 回放文件记录当时 Revision 内容指纹，回放时装那一版。旧版产物按保留政策留存，避免回放 404。保留时长是运营策略，不进本决议。
5. 导表 ≠ 上线。本仓 CLI 没有激活动作。

## 明确不做

- 不做生产运行中热更。
- 不在本仓实现运行时装载器或回放播放器。2026-09-02 Owner 按「如无必要勿增实体」把 Workflow R-00326 收窄为本仓侧合同：manifest 的 Revision 身份字段、指纹不匹配 / 必需表缺失 / 根混用三类负向 fixture、`docs/reference/revision-manifest.md`；装载、reload、握手、回放待运行时仓需要时在其 Room 立卡。
- 不在本决议占用架构仓 ADR 号。
