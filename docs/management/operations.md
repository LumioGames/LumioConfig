# 日常管理与操作

## 角色

| 角色 | 权限 |
| --- | --- |
| Author | 通过补丁或 Pull Request 提议源表变更，运行本地预检 |
| Machine Gate | 校验格式、类型、引用、四态和可见性，生成结构化错误 |
| Owner | 查看语义摘要、模拟/披露信息并签署生产 Revision；首版只保留流程边界 |
| Consumer Maintainer | 在实现仓接收锁定版本的只读导出物，不改源和生成物 |
| AI | 查、提案、预检、预演、提交；没有激活动作 |

## 日常流程

1. 读取表 Schema 和当前基线。
2. 修改 `tables/` 或 `schemas/`，保留稳定行名和永久行号规则。
3. 运行 `validate`，修复结构化错误后再提交 Pull Request。
4. 运行 `format --check`，保证文本排版可重复。
5. 运行 `export` 生成本地三端预览，检查隐藏列没有进入客户端投影。
6. 在评审中附命令输出、指纹和 known gaps。
7. 生产生效另走人门签名和实现仓发布流程；导出命令本身不具备该权限。

## 版本和回滚

- 源表历史由 Git 保存；导出 Revision 由 manifest 的源提交和三重指纹定位。
- 回滚优先重新导出已验证的旧提交，不在生成目录手工替换文件。
- 生产实例一生绑定一份完整 Revision；旧回放使用它记录的 Revision 指纹。
- 真实保留时长、签名信任链和跨仓自动分发在阶段 0 ADR 和后续阶段实现前不视为已冻结。

## 事故处理

- 校验失败：保留结构化错误，修复源或 Schema，不绕过门禁。
- 导出指纹变化：先比较逻辑内容、Schema 和源提交，再判断是否为预期变化。
- 客户端出现不应公开的列：立即停止发布，撤销待发布 Revision，保留证据并回报 Owner；不要用加密掩盖投影错误。
- 发现公共契约缺口：暂停本仓实现，向架构仓提交缺口描述，不在本地发明兼容字段。
