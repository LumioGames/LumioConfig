# C# typed Table Reader（M8 冻结接口）

本文是 Runtime R-00544（M9 装载器）的冻结接口。导表器 `export --csharp-out` 按本文生成只含类型与读法的 C# 源码；数值一律来自运行时装载的 JSON 文件，生成物内不得出现任何表格行数据。

权威依据：

- 架构仓 ADR-077 决策 3：数据必须是文件；M8 生成的 C# 只含类型与读法、不含数值。
- 架构仓裁决流水 §2.3：JSON 只在 M9 装载时解析一次，快照存按 schema 生成的强类型，Reader 直接返回类型值。
- 架构仓 `config-table.md` M8：`TryGet(编号)` 同步返回、绝不读盘；将来文本换二进制只换内芯。
- Runtime `ConfigTableColumnsItemType` 列类型词表（`bool` / `i32` / `i64` / `u32` / `u64` / `f32` / `f64` / `string` / `enum` / `ref`）。

本仓不实现运行时装载器。`GeneratedConfigArtifactView` 的解析、指纹校验与快照激活归 Runtime M9。

## 生成命令与目录

```text
python tools/lumio_config.py export --out <dir> --csharp-out <dir>
```

`--out` 的 JSON 字节合同不变。`--csharp-out` 另写一份 C# 源码树，按端切分：

```text
<csharp-out>/
  server/<Table>Table.cs
  client/<Table>Table.cs
  voxel/<Table>Table.cs
```

端目录与 JSON 投影一致：`S` → `server`，`C` → `client`，`V` → `voxel`。每端只生成该端可见列（Schema `visibility` 含该端字母）。一张表一端一个 `.cs` 文件，内含 `<Table>Row` 与 `<Table>Table`。

`--csharp-namespace <name>` 可选，默认 `Lumio.Config.Generated`。实际命名空间再按端追加一段：

| 端 | 目录 | 命名空间 |
| --- | --- | --- |
| S | `server/` | `<root>.Server` |
| C | `client/` | `<root>.Client` |
| V | `voxel/` | `<root>.Voxel` |

未传 `--csharp-out` 时不写 C#，既有 `--out` 行为与字节保持不变。

## 列类型映射

Schema 列 `type` 与 Runtime `ConfigTableColumnsItemType` 词表一致。C# 字段类型按下表映射；`required: false` 的列在 C# 上为可空（引用类型保持可空注解，值类型加 `?`）。

| Schema `type` | C#（必填） | C#（可选） | 备注 |
| --- | --- | --- | --- |
| `bool` | `bool` | `bool?` | JSON 布尔 |
| `i32` | `int` | `int?` | |
| `i64` | `long` | `long?` | |
| `u32` | `uint` | `uint?` | |
| `u64` | `ulong` | `ulong?` | |
| `f32` | `float` | `float?` | 有限值；负零归一为 `0.0`（源规则） |
| `f64` | `double` | `double?` | 同上 |
| `string` | `string` | `string?` | NFC 归一化后的文本 |
| `enum` | `string` | `string?` | 闭集 `enumValues`；生成物不另发枚举类型 |
| `ref` | `uint` | `uint?` | 目标行终身编号；JSON 投影里可能是十进制字符串，M9 解析成 `uint` |

`id` 列（Schema `idColumn`，默认 `id`）在生成的 Row 上固定名为 `Id`，类型按该列 schema 映射（首版三张表示例均为 `u32` → `uint`）。其余列的 C# 属性名为 snake_case 列名的 PascalCase（`display_name` → `DisplayName`，`cooldown_frames` → `CooldownFrames`）。

Rust 一路本仓本卡不生成。Rust 应对齐同一套列名、同一套类型宽度与同一套 `TryGet(id)` / 有序遍历 / `Count` 语义；标识符用 Rust 习惯（`snake_case` 字段、`u32`/`i32` 等），不另发明词表。

## 生成文件头

每个 `.cs` 文件以自动生成头开始，且必须包含「生成物不得手改」。头里钉的是 **schema 指纹**，不是内容指纹：改行数值不得改生成物；改列类型 / 可见性 / 列名 / `idColumn` 必须改生成物。

```csharp
// <auto-generated>
// 生成物不得手改。由 LumioConfig `export --csharp-out` 重建。
// table: skills
// target: S
// schemaFingerprint: <64 位小写 hex>
// </auto-generated>
```

`schemaFingerprint` 是对该表 Schema 中影响读法的字段做 canonical JSON 后的 SHA-256 hex（列按 `ordinal` 排序）：`table`、`idColumn`、每列的 `name` / `ordinal` / `type` / `required` / `visibility` / `enumValues` / `refTarget`。不含行数据、不含 `default` 数值、不含 `minimum` / `maximum`（范围由机器门在导表时强制，不进入 Reader 签名）。

UTF-8、LF、文件末尾换行。同源两次生成必须逐字节相同。

## `<Table>Row`

每表一端一个 `readonly struct`。字段只覆盖该端可见列，按 `ordinal` 升序声明。无 setter、无可变集合、无行字面量。

```csharp
public readonly struct SkillsRow
{
    public SkillsRow(
        uint id,
        string name,
        uint effectId,
        int damage,
        int cooldownFrames)
    {
        Id = id;
        Name = name;
        EffectId = effectId;
        Damage = damage;
        CooldownFrames = cooldownFrames;
    }

    public uint Id { get; }
    public string Name { get; }
    public uint EffectId { get; }
    public int Damage { get; }
    public int CooldownFrames { get; }
}
```

上例是 `skills` 的 **S** 端。同一张表的 C 端没有 `effect_id` / `damage` / `cooldown_frames`，而有 `display_name` / `icon`。构造函数参数顺序与属性声明顺序相同，均为 ordinal 序。

可选列在构造函数与属性上都是可空类型；缺列时由 M9 传入 `null` / `default`，生成代码不读 Schema `default` 数值。

## `<Table>Table`

每表一端一个 `readonly struct`，持有按 `Id` 升序的只读行列表与按 `Id` 的查找表。构造之后不再读盘、不再解析 JSON。

```csharp
public readonly struct SkillsTable
{
    public SkillsTable(IReadOnlyList<SkillsRow> rows) { /* 按 Id 升序拷贝；重复 Id 抛 ArgumentException */ }

    public int Count { get; }

    public bool TryGet(uint id, out SkillsRow row);

    public IReadOnlyList<SkillsRow> Rows { get; } // Id 升序，与构造时排序后的序列相同
}
```

签名约束：

- `TryGet(id, out row)`：`id` 类型与 Row 的 `Id` 相同。命中返回 `true` 并写出该行；未命中返回 `false`，`row` 为 `default`。同步、无 I/O、无分配要求（实现可在构造时分配索引）。
- 有序遍历：`Rows` 按 `Id` 升序。`foreach` 该列表即遍历。不得按源文件行号或名字排序。
- `Count`：行数，等于 `Rows.Count`。
- 构造函数只接受已经类型化的 `IReadOnlyList<TRow>`。**不**接受 `GeneratedConfigArtifactView`、JSON 文本或文件路径——那些属于 M9。M9 在装载时按 schema 解析一次，把每行变成 `<Table>Row`，再交给本构造函数。
- 重复 `Id` 视为装载错误，构造时抛 `ArgumentException`。生成代码不吞错误、不静默覆盖。

游戏代码只许通过 `<Table>Table.TryGet` / `Rows` / `Count` 读表，不许自己拆 JSON。

## 与 M9 的分工

| 步骤 | 所有者 | 输入 | 输出 |
| --- | --- | --- | --- |
| 导表 JSON | LumioConfig `export --out` | `tables/` + `schemas/` | `server\|client\|voxel/<table>.json` + `manifest.json` |
| 生成 Reader | LumioConfig `export --csharp-out` | 同上 Schema（不含行） | 本文件描述的 `.cs` |
| 解析一次 | Runtime M9 | export 目录 + 端标签 | `GeneratedConfigArtifactView` → 强类型 `TRow[]` |
| 绑定 | Runtime M9 | `TRow[]` | `<Table>Table` |
| 帧内查询 | 玩法 | `id` | `TryGet` 返回的 `TRow` |

M9 不得在 Runtime 内存里另存一份表结构；列集合、顺序与 C# 类型以本生成物为准。换二进制内芯时只替换 M9 的解析，不改本签名。

## 确定性与「只含类型」证据

1. 同一份源、两次 `export --csharp-out`，对应 `.cs` 逐字节相同。
2. 只改 `tables/` 行数值（类型、列、可见性不变）再生成，`.cs` 字节不变。
3. 改某一列 `type` / `required` / `visibility` / 列名 / `idColumn` 再生成，且仅对应表的 struct 签名变化。
4. 对生成目录 `grep` 不到源表里的行数值（例如 `40001`、`fireball`、`120`）。schema 指纹 hex 与标识符（表名、列名）不是行数值。

## 本卡不做

- 不生成含行数据的 C#（没有 `new SkillsRow(40001, "fireball", …)`）。
- 不实现运行时装载器、reload、握手、回放。
- 不改 `export --out` 的 JSON 字节。
- 不生成本卡范围外的 Rust 源码。
