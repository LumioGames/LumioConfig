## 背景（一句话）

编辑器要支持「新建表」需要同时产出 `schemas/<t>.json` + `tables/<t>.txt` + `registry/` 的行号命名空间条目；**ID Namespace 授权归架构仓**（本仓 `.spec/AGENTS.md` 红线 5、架构 ADR 0-2 镜像 `docs/decisions/0-2`）。弄错命名空间会让两个仓的表撞号，且撞号不可逆（终身编号一旦发出就不能改）。

## 六个问题（逐条需要架构仓的明确回答）

1. **命名空间归属**：新表的终身编号命名空间怎么分配？由谁授权？
2. **自治区段**：本仓工具（`lumio_config.py table new`）能否自行分配一个未占用区段，还是必须逐表走架构仓登记？
3. **集中登记流程**：若必须集中登记，登记的入口、材料与回执是什么（Workflow 卡 / ADR / 其他）？
